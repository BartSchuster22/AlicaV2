## K7/K9 semantics / limitations
PUBLIC CONTRACTS ONLY. No duplicate persistence, stateless adapter. No native idempotency promise: all ACAP operations idempotency:none, ACAP idempotencyKey rejected; create accepts an explicit requestKey as best-effort backend lookup hint, scoped by trusted board+actor hash. Sequential replay may return old task; backend concurrent create race and no content conflict check are documented, adapter must reject content mismatch if observed, not promise uniqueness. Comments have no dedupe; repeated calls append repeated comments. Update is last-writer-wins; no CAS/stale rejection, expectedVersion input forbidden rather than falsely enforced. Concurrent outcomes represented as actually returned, tests exercise last-writer-wins. Never automatically retry mutations. On transport/decode/status5xx/timeout after possible send, return {outcome:UNKNOWN, task:[], requestKey:...}; APPLIED create/update return exactly one current normalized task in task:[task], APPLIED comment returns task:[] (the comment endpoint only confirms storage, and a second read is not required to reinterpret success). UNKNOWN always task:[]; requestKey echoes the supplied create key for create and is the empty string for update/comment, which have no dedupe key. A subsequent read may show current state but cannot prove that request committed. Backend reported success maps APPLIED, not durable exactly-once. On response loss or broker deadline/cancellation/disposal, even if ACAP returns DEADLINE_EXCEEDED/CANCELLED/UNAVAILABLE, consumer MUST treat mutation as UNKNOWN; it is stop-waiting, not rollback or execution termination. Internal HTTP budget at most600ms, smaller than remaining broker deadline minus50ms; upstream body<=256KiB; active<=4. Backend restart test within same private state namespace; adapter restart no metadata recovery necessary. Cleanup aborts adapter HTTP/WS only, never backend server/work.

## K12 selected event delivery
Board/list inspect the full returned columns only within the256KiB body bound. More than256 tasks or oversized response fails RESOURCE_EXHAUSTED; no clamped taskCount, silently truncated subset or pagination claim. Events advance cursor ONLY over the inspected prefix: before the first selected event that would exceed caller limit STOP without inspecting/advancing past that event. Returned selected events are all selected events within that prefix. Never copy backend frame.cursor over omitted rows. Malformed/out-of-order/oversized frames fail without advancing the caller cursor. Tests include257-task board/list,33 selected events with limit32 and limit1 repeated polls, unselected event prefixes, and malformed frames.

Public unary bounded `events(board,cursor,limit)` poll bridges documented authenticated WS `/events?board=...&since=...`, waits<=400ms, one batch maximum200, returns max32 normalized selected created/edited/commented events, cursor of last inspected (not merely emitted) event; unselected events advance cursor without inventing lifecycle. Contract continuity=UNKNOWN always including initial/reconnect/expired/future cursor because backend no retention watermark and board snapshot/cursor not atomic. Empty timeout is no observation, not no changes. Each event ID opaque numeric string, board-scoped provider order; task and event type, observed timestamp only, no provider payload. Consumers deduplicate (board,eventId); same cursor replay duplicates by design. No durable adapter subscription or cursor store. Reconnect: caller polls supplied cursor and separately board/get/list reconciles current state; never clears historical uncertainty. Backpressure: pull only, active<=4, frames<=256KiB, events<=32, wait bound; too large/malformed => explicit error or UNKNOWN gap, never silent complete truncation. Cancellation/revocation closes owned socket. Polling not native ACAP push or lossless delivery; K4 typed events proves availability but unnecessary event-bus additions avoided.
