# ADR-013 R2 — Authenticated local IPC with bounded concurrency

Status: **OWNER APPROVED FOR IMPLEMENTATION** — see [concrete approval](../gates/G6-R2-OWNER-APPROVAL.md). Runtime qualification remains pending.

The [owner direction](../gates/G6-CONCURRENCY-DIRECTION.md) approves retaining the native Linux bridge/locked C toolchain and replacing the single-active exit target. This revision supersedes the earlier ADR/profile, not frozen G1 semantics. The concrete R2 mechanisms and schemas remain subject to the recorded review gate.

Use Linux x86-64 Unix-domain IPC, native peer credentials/pidfds, a small private C bridge/launcher, Landlock and seccomp. Keep protocol, grants and lifecycle policy in TypeScript. No containers, orchestration, production Python runtime or private Node `_handle` dependency. Other platforms fail closed until independently qualified.

One provider process retains **one module instance and its mutable state**, serving several invocation contexts. Do not replicate the provider per call or serialize the equivalence suite. Broker-created context endpoints supply authoritative invocation association. A received parent ID is not provenance.

A compromised shared process can use any legitimate context capability it possesses. This design enforces the authority, scope, deadline and cancellation of the endpoint actually used; it **does not prove the semantic origin of computation or prevent deliberate use of another legitimately held endpoint**. Such use cannot revive the original call, deliver its result, inherit its consumer's authority or exceed the selected endpoint's provider permissions. Hard confidentiality between computations inside one compromised process is not claimed. Root/the operator account, kernel and pinned runtime/native bridge are trusted. Process death is a shared failure domain for its sibling calls.

## 2. Native identity and immutable launch binding

The supervisor records the expected Cell, physical instance, package/inventory digest, accepted descriptor/version/feature vector, runtime/bridge digests, UID/GID, spawned PID, pidfd, session/generation and a fresh single-use challenge. Verified package bytes are captured before launch into sealed read-only storage; execution does not reopen mutable unverified entrypoint paths.

Create a random private runtime directory (0700), with an absolute, non-abstract UDS stream endpoint (0600). The trusted launcher connects **from the child**, and execs the pinned Node binary without changing PID. Native accept obtains SO_PEERCRED and compares actual PID/UID/GID against the launch record and live pidfd. Never authenticate by provider name, executable name, argv or an asserted PID. A parent-created socketpair's credentials do not prove the child's PID.

Send the challenge on a dedicated inherited channel, not argv/environment. Authenticate hello against the exact launch record and expected descriptor vector before activation. Features do not grant authority. One authentication attempt per connection; stale challenge, replay, digest/identity mismatch or unsupported required features fail closed. Never signal a PID supplied by a peer; only the supervisor's owned launch pidfd is a termination target.

## 3. Invocation-bound channels

Retain the authenticated instance **control stream**. Add a private inherited AF_UNIX/SOCK_SEQPACKET descriptor carrier created by the trusted supervisor and handed only to that launched process. Its authority comes from exclusive launch inheritance plus the authenticated launch/control association, not from an invented child credential on the parent-created pair.

For each admitted invocation, event callback, provider task or lifecycle action:

1. Reserve the appropriate scheduler slot, byte/FD budget and monotonic deadline before allocation.
2. Create a fresh UDS stream socketpair. The broker retains one endpoint in an immutable context record, including parent, scope, grants, deadlines and descendants.
3. Send the other endpoint in exactly one native carrier packet with a fresh offer ID and `context-offer.schema.json` metadata. There is exactly one SCM_RIGHTS descriptor; descriptor numbers are never ACAP values or authentication claims.
4. The trusted receiver consumes the whole packet with recvmsg/MSG_CMSG_CLOEXEC. Validate length, ancillary count/type, stream socket type and offer metadata; close every rejected descriptor. Reject truncation, duplicate/mismatched offers, unexpected ancillary messages and surplus descriptors.
5. A `context-ready` acknowledgement on the authenticated control stream must match the one pending offer. It grants no new authority. An expired work context stays invalid, but an unacknowledged transfer retains its reservation until an authenticated fresh-nonce acknowledgement proves carrier consumption. The unpredictable offer nonce is disclosed only in the carrier packet. A hard offer timeout fails the physical session; retain unreaped/in-flight resources until consumption or observed process/carrier destruction, rather than pretending a queued descriptor was recalled. Only after readiness does the broker dispatch invoke/lifecycle/event work on its context stream. A provider-task context becomes usable after the matching ready acknowledgement.
6. The broker routes nested requests from the **receiving endpoint record**. The header's context ID must agree with that record but cannot retarget it. `parentWireId` is removed from outbound schemas. An outbound request cannot assert a caller. Requested budget can only shorten the broker-derived parent budget.

Control and context streams retain 4-byte big-endian length-prefixed canonical JSON. Carrier packets have their own bounded packet decoder: never read a seqpacket prefix with a stream reader that discards the packet remainder. Carrier metadata is native transport plumbing, not application payload or a host object exported through ACAP.

Raw numeric fd reuse must not rebind a context. Native lease objects, endpoint ownership and generation checks must fence late callbacks. Close all context endpoints atomically on physical-session loss. No automatic replay or transparent rebinding of old handles.

## 4. Bounded scheduling and reentrancy

Per worker reserve four ordinary slots plus four nested/reentrant slots, with at most eight application contexts active or awaiting offer acknowledgement. One additional lifecycle slot is reserved. Ordinary calls, provider tasks and event callbacks cannot consume the nested reserve. Nested work uses a reserved slot first, then an unused ordinary slot. If neither is available, reject immediately with RESOURCE_EXHAUSTED; do not queue a nested call behind its blocked ancestors.

Allow repeated visits to a provider in a causal chain, including A-to-B-to-A, while capacity and maximum depth eight permit. Depth and ancestry are broker-derived. This prevents admission deadlock, not arbitrary deadlocks in provider application locks; original deadlines still apply to those.

At most 64 ordinary pending calls are queued FIFO per worker, subject to the shared byte/frame budget. Their clocks start at original submission. Expired/cancelled queued work never receives an endpoint or a fresh timeout. Release reservations once, dispatch queued work fairly, and keep lifecycle/cancel control capacity independent of ordinary saturation.

The same logical scheduler/limits apply to both equivalence factories. Native descriptors are IPC-specific plumbing, not a consumer-visible API requirement. A single-active setting may be a diagnostic fixture, never the final concurrency qualification.

## 5. Authority, causal budgets and instance state

At each operation and delivery, the broker checks the authenticated provider instance, permitted context scope, owned bound handle, declared requirement, accepted digest, live generation and current grant/expiry/revocation. The inbound observational caller tuple is not transferable authority. Scoped handles cannot be widened by a body field. Child-scope creation alone issues no grants; permitted scope changes require broker-validated ownership and explicit grant checks.

A nested deadline is the minimum of remaining parent budget, requested budget and operation/profile limits, including time spent queued and handing over endpoints. Parent cancellation, expiry and revocation invalidate descendants before new work or data is exposed. Unrelated calls retain their own deadlines and cancellation. Do not substitute a process-wide earliest deadline.

The SDK dispatcher routes asynchronous handler work using the corresponding endpoint. AsyncLocalStorage aids routing, but is not the authorization boundary. Long-lived bound handles remain bound to provider identity/scope; each invocation uses the current causal endpoint. An expired retained context fails: it never silently falls back to a new provider task.

Background activity is explicitly admitted through `task-open` using the provider's own declared/granted scope, an independent trace/root budget and ordinary capacity. It does not inherit any consumer authority or renew a previous invocation. The broker may deny it by lifecycle, grant or resource policy. A malicious shared process can request independent work under its own permissions; it cannot make that work a continuation/result of an expired consumer call. This limitation is explicit, not hidden behind an opaque ticket.

## 6. Confinement and build provenance

Keep one pinned Node module instance per worker. Use the already pinned Node archive and its public N-API headers. The proposed project-local C compiler is Zig's bundled C frontend **0.15.2**, pinned by URL, SHA-256 and archive size in `draft/native-build.lock.json`; use it to build C glue, not Zig ACAP application logic. The index metadata was retrieved; the archive/build has not been qualified. No compiler installation is performed by this design revision. After approval, integrate the build lock/provenance under existing dependency controls; no sudo/global compiler or service installation is required by the design.

The launcher permits only explicit bootstrap descriptors: stdio, the child-connected control stream, challenge, sealed code capsule and inherited carrier. Close everything else; whitelist environment instead of subtracting known secret names. Use empty stdin and discard raw provider stdout/stderr by default. Never propagate NODE_OPTIONS, LD_* or parent credentials. Supply an explicit empty read-only OpenSSL configuration; the earlier probe showed the ambient configuration lookup can prevent restricted Node startup.

Before untrusted code, install no-new-privileges, Landlock read/execute rules for the exact pinned runtime/library/SDK/package closure, with no writable host paths or inherited directory handles. Filesystem metadata invisibility is not claimed. The private native receiver permits recvmsg only on the fixed carrier descriptor; its resulting context sockets are legitimate broker-issued resources. Deny worker SCM_RIGHTS transmission, arbitrary socket creation/connect, alternate network/io_uring paths, process creation, exec after startup, ptrace/process-vm/pidfd-getfd, mount/namespace changes, host metadata modification and signaling/resource changes to other processes. Reject compat/x32 syscall paths rather than permitting syscall-number bypasses.

Warm the declared runtime thread pool before final sealing; cap total threads at 16, deny further clone/fork paths and synchronize final seccomp across all existing threads. Reapply dumpability protections after exec; prevent the worker from clearing parent-death termination. Qualify these controls on the actual pinned Node/native build; the socket-only Python probe is not the final filter.

Proposed process ceilings retain: at most four provider processes, 64 descriptors per worker, 512 MiB RLIMIT_DATA, 8 GiB address-space limit, 64 MiB V8 old-space, no core/filesystem output, 120 CPU-seconds per worker lifetime, and the documented pinned Node startup flags. These are resource-policy limits, not a claimed exact RSS cap or production performance guarantee. Bootstrap descriptor/thread counts must fit with all context slots occupied; failure must reject launch rather than silently relax confinement.

## 7. Failure, cleanup and evidence

First terminal outcome wins; peer loss produces UNAVAILABLE unless a specific cancellation/deadline/revocation result already committed. Side effects may have occurred before disconnect: do not automatically replay mutations, even with an idempotency key. Normalize errors/correlation in the broker and discard arbitrary provider diagnostics.

On unload, revoke/invalidate owned contexts and published handles before disposal. Allow 500 ms cooperative cleanup, then 500 ms TERM grace, then SIGKILL through the owned pidfd with 500 ms reap-observation budget. Record actual overshoot and failure; process exit is authoritative, not a provider cleanup assertion. Killing an uncooperative shared worker also fails sibling contexts. Apply bounded heartbeat/reconnect policy from the profile; reconnect creates a fresh physical instance/session and does not rebind old handles or reset the attempt budget on a mere hello/pong.

The current checks exercise schema shapes, an abstract endpoint/scheduler model and a disposable Linux carrier primitive. They do **not** establish native authentication implementation, complete syscall confinement, Node transport equivalence, live grant revocation or forced-termination qualification. Those remain implementation exit tests after review.
