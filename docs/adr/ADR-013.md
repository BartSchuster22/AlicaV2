# ADR-013 — Authenticated local IPC and restricted provider processes

Status: **REVISION REQUIRED — bounded-concurrency direction approved; revised ADR/schema review remains pending**.

The owner approved replacing the restricted single-active equivalence target with bounded concurrency and reentrancy. Native Linux bridge and locked C-toolchain direction are retained. See [owner decision](../gates/G6-CONCURRENCY-DIRECTION.md) and [revision requirements](../g6/CONCURRENCY-REVISION.md). The remaining text records the prior proposal, not an approved implementation design.

Prerequisites: G5 accepted for `db74818`; IPC baseline approved in `G6-BASELINE-APPROVAL.md`. This ADR completes implementation choices, not G6 qualification. Frozen G1 documents remain unchanged. Draft schemas: `docs/g6/draft/frames.schema.json`; protocol rules: `docs/g6/IPC-PROFILE.md`.

## Proposed decision

Linux x86_64 local Unix-domain stream sockets; existing 4-byte big-endian framing and constrained UTF-8 JSON. Keep protocol, grant enforcement, SDK integration and consumer logic in TypeScript/Node. Add a small, auditable native Linux bridge/launcher for facilities unavailable through supported Node APIs: accepted-socket `SO_PEERCRED`, pidfds, sealed launch material, Landlock and seccomp. Do not depend on private Node `_handle` fields or use Python as the production supervisor. Python remains design/test tooling.

No containers, Docker installation, orchestration, host-wide namespace changes or privileged service installation are selected. IPC does not qualify container support.

**Dependency approval:** the native component and a hash/version-locked C build toolchain are additions to the G2 build policy and require this ADR's approval. `gcc`/`cc` and `bwrap` are absent on the target. No compiler has been installed. Native sources, syscall filters, headers, build provenance and binaries must be reproducibly built and reviewed; no opaque downloaded helper is accepted as a substitute. Unsupported platform capabilities fail closed, not to an unconfined process.

## Authentication and launch sequence

1. Broker completes existing publisher trust, freshness, revocation, inventory and descriptor verification before accepting a package for launch. Capture verified executable graph bytes; do not later reopen mutable plugin source paths as authoritative content.
2. Create a per-launch private directory (`0700`) and a filesystem UDS (`0600`) under an operator-owned parent, using secure creation and rejecting symlink substitution. No abstract socket, TCP listener or discoverable bearer-token file.
3. Mint a fresh session ID, challenge and physical instance ID; advance a monotonic session generation. Store a private launch record containing package/inventory digest, accepted descriptor/feature vector, expected UID/GID, child PID, pidfd and immutable instance/scope associations.
4. Spawn the trusted launcher with an explicit environment allowlist, closed ambient descriptors and no shell. Pass verified source material via sealed, size-bounded launch descriptors and challenge material via a private descriptor, not argv/environment. No signing keys, host grants or inherited secret values are supplied.
5. The **child** connects to the listener. Read kernel `SO_PEERCRED` and require exact launched PID/UID/GID plus a live matching pidfd. Do not use a socketpair created in the parent as proof of the child's PID: its peer credentials can describe its creator. An unexpected peer is disconnected; never signal a PID supplied by a frame or an unexpected peer.
6. Launcher applies no-new-privileges, descriptor closure, limits and filesystem confinement, then directly execs the pinned Node runtime without changing PID. Trusted bootstrap installs the final syscall seal before any provider code runs. Runtime, native bridge and allowed dependency closure are pinned operator TCB material, not provider assertions.
7. Bootstrap sends one `hello` proving possession of the launch challenge and proposing exact package, Cell, instance and descriptor bindings. Broker verifies it against the launch record and consumes the challenge once. A correctly formatted provider name or digest is **not** authentication.
8. `accepted` fixes protocol/features/limits. Activation is separately requested and bounded; staged registrations become visible only after successful activation. Failure rolls back owned effects. No application traffic is admitted during the handshake.

The operator account and root remain trusted. This is not a promise of protection against an unsandboxed attacker controlling the supervisor's UID, host root, a compromised kernel or a compromised trusted runtime. Provider-authored code is untrusted within its restricted worker.

## Isolation profile

Propose Landlock ABI >=3 and architecture-checked seccomp; no reliance on currently unavailable user namespaces.

- Filesystem: read/execute only the pinned runtime, precisely enumerated shared-library/public-runtime dependency closure, explicit read-only OpenSSL configuration and verified provider material. No whole home, repository, `/proc`, `/sys`, host configuration or credential-directory read grants. No ambient writable filesystem. If a later operation requires scratch storage, it must be separately bounded, instance-owned and reviewed.
- Network: only the established authenticated UDS descriptor. Deny new sockets and connection/listener creation after setup. Block io_uring paths which could bypass simple socket syscall checks. No inherited network descriptors.
- Process control: deny fork/vfork, namespace/mount changes, ptrace, process_vm operations, pidfd acquisition/descriptor stealing, BPF/perf/keyring facilities and cross-process signalling. Warm a fixed Node/libuv thread pool during trusted bootstrap, cap it at 16 threads, then deny further clone/clone3/fork/vfork with a TSYNC filter on every existing thread. Unexpected thread requirements fail qualification rather than weakening the filter. Apply a second seal denying exec/execveat after bootstrap. Block filesystem ownership/mode mutations that Landlock alone does not mediate. The final architecture-specific filter requires native tests; the probe's socket-only filter is insufficient.
- Environment: construct from an allowlist (locale/timezone only unless explicitly justified); no inherited `NODE_OPTIONS`, loader/preload variables, credentials, SSH agent socket or arbitrary `PATH` lookup.
- Limits proposed for initial qualification: 64 descriptors, no core dumps, 512 MiB data limit, 8 GiB address-space limit, 64 MiB V8 old-space, JITless mode, disabled WASM trap handler. These are not an RSS/cgroup guarantee. Limit concurrent workers to four, warm at most 16 threads per worker before sealing, and set a 120-second hard CPU-time limit per synthetic qualification worker (not a replacement for per-call deadlines). Set parent-death SIGKILL with a parent-identity race check and prevent the provider from clearing it. These are initial synthetic qualification limits, not an unrestricted long-running production service profile. Exceeding limits is a deterministic failure, not a fallback to weaker confinement.
- Output: drain bounded stdout/stderr without deadlocking; discard raw content by default and audit only bounded counters/status codes. Safe SDK structured logging uses its closed vocabulary through the authenticated broker.

Landlock restricts file access, not every filesystem metadata observation. Resource exhaustion, shared-kernel defects and side channels are not eliminated. Final negative tests must test syscall escape routes, not merely the ordinary `fs`/`net` APIs.

## Measured design feasibility

Target: Linux `6.8.0-139-generic`, x86_64, unprivileged UID/GID 1000, pinned Node `24.21.0`.

- Kernel peer PID matched the separately launched connecting child's PID; pidfd acquisition succeeded; socket mode was `0600`.
- User-namespace setup failed with `Operation not permitted`; `bwrap` is absent.
- Landlock ABI query returned 4.
- A disposable Node child under Landlock, a socket-denying seccomp probe and the memory/descriptor/CPU probe limits could read its allowed fixture. Outside read/write, allowed-file write and symlink escape returned `EACCES`; network socket creation returned `EPERM`; the synthetic parent secret was absent.
- Initial startup failed on OpenSSL's ambient `/etc/ssl/openssl.cnf` lookup. Supplying an explicit empty read-only configuration fixed startup; widening host configuration access was not necessary.

See `evidence/g6-design/`. The probe uses broader library-directory reads than the proposed final file closure and only a socket-denying syscall filter. It is **not a production launcher, authentication implementation, complete sandbox test or transport-equivalence result**.

## Cleanup and recovery

A terminal session transition atomically invalidates its handles, cancels deliveries, fails outstanding work and unpublishes registrations. Provider death/disconnect yields `UNAVAILABLE`; an already committed cancellation, revocation or deadline outcome is not overwritten. Never automatically resend a mutation, including one with an idempotency key. Its side effect may have happened before disconnection.

Unload cancels reconnect/backoff, stops admission, requests cooperative disposal for at most 500 ms, sends SIGTERM with 500 ms grace, then SIGKILL through the recorded pidfd and allows 500 ms to observe reaping. Record elapsed time and scheduling overrun. Failure to reap is FAILED/restart-required, never a clean DISPOSED report. A worker's cleanup report is advisory; supervisor observations determine completion.

Transient connection failure permits at most four fresh launches at 1, 2, 4 and 8 second backoffs. The initial launch is separate; counters do not reset on a successful hello/pong. Trust, policy and grants are revalidated for each new physical instance and session generation. Authentication/contract failures are permanent, not a retry loop. Old handles never rebind; mandatory dependants follow existing quiescence rules. Automatic availability recovery does not imply automatic consumer recovery or grant reissuance.

## Qualification required after approval

The same parameterized consumer function and public interfaces must run over inproc and IPC. Select transport only in the factory. Enforce the same declared message/depth/queue profile on both routes; compare payloads, errors, authority, events, stream ordering and terminal outcomes, not physical instance IDs or exact latency.

Required failures: forged identity, wrong digest/features, captured hello/session replay, PID/FD reuse races, malformed/truncated framing, oversized prefix/body, invalid UTF-8/duplicate keys/non-ACAP values, caller assertion injection, zero/extra credit, stalled streams, all queue bounds, killed process, disconnect during a mutation, revocation with buffered stream items, repeated reconnect, ignored cancellation, unload deadline and forced kill/reaping. Include restricted filesystem/network/process-control attempts and inherited-secret/FD checks. Capture real timings, maximum queued bytes/items and process exit observations.

No G6 exit claim until the production adapter, native launcher, synthetic packaged provider, unchanged consumer suite and hostile-process matrix have actually run. Schema checks and the current feasibility probe cannot satisfy that exit gate.
