Kernel delegates dispatch to the same public runtime. Its authority callbacks still enforce the current instance, scope generation, package trust, provider liveness and grant on admission and delivery. Global pending-call accounting and raw provider-work tracking remain Kernel-owned. Idempotency state belongs to the registered provider, not an individual consumer handle. Public packages cannot import Kernel; the CLI's one computed import is narrowly allowed only in its explicit trusted-provider loader.

`ContractSession` is a host-side adapter, **not an authentication gateway**. Its required authorization callback and authenticated caller binding must be supplied by a trusted host. The independent test harness intentionally authorizes its synthetic fixtures. Do not expose its test binding or host hooks directly to untrusted clients.

## Runtime semantics

### Validation, negotiation and diagnostics

- Duplicate-key/noncanonical-number rejection and bounded integer-only ACAP values remain unchanged. Payloads, descriptors and wire data are detached; accessors, cycles, sparse arrays and non-data values are refused.
- Legal ASCII property names such as `__proto__` and `constructor` remain ordinary JSON data. The finite G1 payload interpreter uses own-key semantics, and generated descriptors are parsed JSON rather than JavaScript object literals.
- Descriptors enforce the frozen schema plus semantic checks: unique operations/features, numeric version bounds, coherent payload constraints, required-property references and idempotency policy consistency. G1 canonical vectors remain in the regression suite.
- Required version/operation/feature mismatch is `INCOMPATIBLE_VERSION`. Optional features are intersected with those provided; absent optional features do not deny binding. Exact descriptor mismatch is `CONTRACT_MISMATCH`.
- Calls have closed request envelopes: caller identity, scope generation and authorization cannot be asserted by adding JSON fields. Unknown operations are `NOT_FOUND` after authority checks. Invalid input is `INVALID_ARGUMENT`; invalid provider output is `CONTRACT_MISMATCH`.
- Errors use the G1 code set. Only code, fixed safe message, correlation ID and `retryable:false` leave the normalizer. Raw provider messages, stacks, private details and values are not copied. Recognizing a code does not depend on an exception's class or realm. Response decoding preserves the broker's correlation ID.

### Deadlines and cancellation

`effectiveDeadline = min(request deadline, inherited deadline, admission time + host maximum)`.

The adapter checks the absolute deadline and an elapsed monotonic budget, propagates deadline/signal through nested sessions, and rechecks before delivering data. Already expired/cancelled calls never dispatch. Duplicate outstanding request IDs are `CONFLICT`. Explicit cancellation uses the request ID; native AbortSignal is a local convenience, not serialized authority. Success, error, deadline and cancellation compete for one terminal result. Late results are not delivered, admission cleanup runs once, and cancellation after completion is a no-op.

Cancellation does not undo external side effects. Uncooperative trusted code cannot be forcibly stopped inside the shared process; G3 work tracking/restart-required behavior remains relevant.

### Idempotency

- `none`: keys are rejected. There is no automatic retry/replay.
- `provider` with `persistence:instance`: the provider adapter keys records by caller principal, scope and generation, capability, operation and key, within that provider instance. Same canonical payload replays the recorded provider outcome; changed payload or an in-flight duplicate returns `CONFLICT`.
- Retention begins when provider work settles. Unexpired records are not evicted to admit another key; capacity exhaustion is `RESOURCE_EXHAUSTED`. Unsettled work retains its key. Fresh provider instances have fresh state.
- Cancellation may finish the caller before underlying provider work settles. A later retry may observe that provider work's recorded outcome. Neither cancellation nor a missing response establishes that no side effect occurred.
- Durable policy is valid descriptor metadata, but this adapter rejects it with `FAILED_PRECONDITION`; it does not pretend an in-memory cache survives a crash.

This is scoped provider-declared replay behavior, **not universal exactly-once execution** or transactional durability.

### Events and streams

The existing Kernel event broker retains validated envelopes, broker-supplied identity/sequence, FIFO subscription delivery, grant rechecks and terminating overflow behavior. Public validators check event descriptor/payload/digest/closed-envelope consistency; schema validation alone does not authenticate a claimed event source.

`BoundedChannel` has finite capacity and a terminal overflow error rather than silent loss. Stream delivery uses zero initial credit; the in-process reader grants credit as it pulls. `CreditWindow` limits outstanding credit to at most 256. Cancellation releases credit and pending readers; slow readers do not cause speculative unbounded iteration. Serialized ACAP values are limited to 1 MiB; queue counts and hence buffered data are bounded. Stream items are validated and authority is rechecked at delivery.

`streamOutcomes` and `readStreamOutcomes` bridge detached logical item/complete/error records, request identity and sequence. Tests serialize them through JSON, including terminal errors. These are **logical contract values, not the G6 IPC frame protocol**. Length-prefix framing, authenticated peer credentials, handshakes, heartbeat/reconnect, OS isolation and IPC per-frame schemas remain G6 obligations.

## CLI

Use the pinned toolchain and repository directory as described in the root README. After `npm ci --ignore-scripts` and `npm run build`, the workspace entry is `npm run alicac -- <arguments>`. Packed installation provides the `alicac` binary. Nothing is published to a public registry.

| Command arguments | Result |
|---|---|
| `capability init --id org.example.echo --out capability.json` | Valid bounded example descriptor |
| `capability validate capability.json --json` | Validation result and canonical descriptor digest |
| `capability generate-client capability.json --out client.mjs` | Deterministic client and `client.d.mts` |
| `capability generate-provider capability.json --out provider.mjs` | Deterministic provider scaffold and declarations |
| `plugin validate plugin.json --json` | Manifest and linked descriptors/entrypoint validation |
| `bundle validate bundle.json --profile profile.json --json` | Inventory lengths/raw digests, indexed content and supplied-profile binding checks |
| `profile validate profile.json --json` | Closed schema, versions, unique IDs, scope tree and declared-pin checks |
| `conformance run --provider fixtures/g4/independent-provider.mjs --fixtures fixtures/g4/conformance.json --descriptor fixtures/g4/capability.json --json` | Machine-readable qualified results; nonzero exit on failure |

Omit `--json` for human-readable output. Unknown flags/fields are refused; generated files are not silently overwritten. Generation embeds canonical descriptor data and contains no timestamp or machine path. Generated provider handlers intentionally fail until authored; **a scaffold is not a qualified provider**.

Plugin/bundle validation reads bounded regular artifacts, rejects symlink escapes, checks linked contracts and inventories, and reports `trustVerified:false`. It does not install, extract an archive, authenticate a publisher, replace Kernel trust verification or establish a production SBOM/offline-distribution claim. The conformance command executes the explicitly selected **trusted** provider module; it is not a sandbox and should be used with disposable synthetic fixtures, not production side effects.

Conformance requires at least one functional oracle for every operation. It checks those expected values/items/errors plus digest mismatch, unknown operation, expired requests, forbidden caller fields and incompatible negotiation. Machine output identifies each check and its result. It cannot prove arbitrary business semantics without meaningful fixtures.

## Gate and remaining limitations

Execution evidence is retained under `evidence/g4`. Clean-checkout qualification is distinct from local tests, and neither is a substitute for the exact candidate's GitHub `foundation` result.

The repository remains private and `UNLICENSED`; no public publishing or license change is authorized here. Required-check enforcement remains unavailable under the current repository plan. Formal G4 PASS requires owner confirmation of the exact candidate's CI result and explicit acceptance. G5 has not started.

G3's trusted-process, experimental Node VM loader, protected single-writer trust store, finite lifetime resource budgets, in-memory audit and operational-control limitations remain. G4 supersedes the G3 unary-only/instance-idempotency limitations with the tested functionality described above, **not** with a production transport, durable replay store, untrusted-code sandbox or complete installer.
