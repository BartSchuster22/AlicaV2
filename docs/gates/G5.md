The external job starts fresh author/operator directories under the OS temporary directory. The real path exercised is **operator probe → SDK consumer → generated client → SDK provider**, with explicit grants, signed inventories, invalid-input rejection and verified cleanup. Reports use **PROVIDER / inproc**, not IPC, bundle installation or recovery certification. Executed logs, reports and hashes are under `evidence/g5/` after qualification capture.

## Boundaries retained

- Trusted in-process code only; not an OS sandbox, IPC transport or G6 implementation.
- SDK cannot issue grants, authenticate arbitrary caller metadata or create host authority.
- Optional resolution is ACTIVE-only; mandatory binding can happen during activation, but invocation waits for ACTIVE.
- Testkit is not production enforcement: no signed grant graph, trust persistence, full dependency resolution/quiescing, complete raw-work race model or production audit guarantee.
- Production secret support remains the G3 synthetic adapter; no real secret manager is claimed.
- Owned effects/events are not durable and operations are not exactly-once. Incomplete cleanup is reported rather than called successful.
- Kit distribution remains private/UNLICENSED; no npm publication or offline installer is claimed.
- G1 specification/schema/vector files remain unchanged. G6–G8 and application/service integrations are not started.
