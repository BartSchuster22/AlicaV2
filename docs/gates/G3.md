# G3 — Minimal trusted Kernel and synthetic Echo

Status: implementation candidate; executed evidence is stored under `evidence/g3/`.
Formal owner acceptance and exact-candidate remote CI are separate from local tests.
G2 progression is authorized by [the owner's manual-control disposition](G2-OWNER-DISPOSITION.md).
No G4+ work, V1 service integration, production deployment, or GitHub visibility change is included.

## Delivered surface

- Public `@alica/acap-types` contracts; `@alica/kernel` operator entrypoint; independent
  `@alica/echo-a`, `@alica/echo-b`, and `@alica/echo-consumer` packages.
- Closed, bounded data-only bootstrap/config and manifest parsing. Secret value is
  supplied separately by operator bootstrap and only the `synthetic-test` reference
  is supported. No real application secret or release signing key is introduced.
- Ed25519 domain-separated root/policy/revocation/bundle verification; canonical
  package identity and raw inventory hashes checked before evaluation. Code bytes
  are copied after verification and evaluated from that copy, not reopened paths.
- Monotonic trust metadata/high-water clock state written with file/directory fsync
  and atomic rename; dual-signed root rotation. Untrusted/expired/rollback metadata
  fails closed. Host clock synchronization remains an operator prerequisite.
- Scoped owner tokens, generations, ancestor-only registration visibility; registry
  indexed by scope/capability/version/owner. Grants bind principal, instance, exact
  scope/generation, operations, validity and revision. Child issuance intersects
  a parent record. Plugins cannot issue grants or acquire the Host object.
- Deterministic version/provider/artifact ordering, explanations with exclusions and
  selected digests, explicit qualified profile pins, sorted portable lock output.
  Mandatory bindings stay on their original instance, even if the catalog changes.
- Frozen G1 lifecycle, hidden activation staging, dependency-cycle rejection,
  reverse tracked cleanup, idempotent terminal outcomes and cascading quiescence.
- Detached, validated unary ACAP values, authenticated broker metadata, inherited
  deadlines, first-terminal cancellation, dispatch/delivery grant checks. No retries.
- Bounded FIFO event queues, broker-authored sequence/source identity, exact event
  contracts, grant rechecks at actual delivery, overflow termination and listener cleanup.
- Bounded metadata-only audit and safe plugin log categories; audit capacity failure
  blocks security-sensitive mutations but never emergency revocation/termination.
- Redacted registry/scope/grant/lifecycle/resource introspection and cleanup evidence.

## Exit evidence / test map

The real Node suites live in `tests/kernel/`; they import only the public host API.
The providers/consumer import public **types only**, not Kernel or one another.
`npm run demo` performs both substitutions and asserts zero registrations, listeners,
owned effects, pending calls, scopes and unsettled work after cooperative shutdown.
The generated JSON contains real resolver, audit, registry, grant and lifecycle output.

| Required case | Executed coverage |
|---|---|
| Provider substitution | Echo A and independently written B, unchanged consumer suite |
| Shuffled registration order | A/B and B/A catalogs choose the same artifact |
| Missing/incompatible dependencies | Never reach ACTIVE; denied dependency also blocks |
| Dependency cycles | Rejected before any participant becomes ACTIVE |
| Partial activation | Staging stays invisible; reverse cleanup and failure preservation |
| Double disposal | Same terminal report; no repeated side effect |
| Listener/child cleanup | FIFO delivery, listener removal, nested teardown and stale generations |
| Denied/expired/revoked grants | Resolve and call denial; revocation during work suppresses output |
| Retained stale handles | No rebinding; closed scopes and removed providers invalidate calls |
| Secret denial | Separate declaration/grant; recheck before delivery; value absent from inspection |
| Unload during calls | Cancellation, tracked call cleanup and explicit uncooperative-work report |
| Additional trust/parser checks | Tamper, wrong signer, rollback, rotation, duplicate JSON, bounded values |
| Cross-language bytes | Runtime checked against frozen Python/OpenSSL canonical byte/digest vectors |
| Profile/explanation checks | Explicit pin controls real execution; planning leaves runtime registry unchanged |

Retained G1 Python tests remain **design checks**, not substituted for these runtime tests.
The import, formatting, type, lock/license and known-credential checks remain release checks.

## Deliberate G3 limits — not hidden claims

1. **Trusted same-process code is not sandboxed.** `SourceTextModule` evaluates the
   already verified standalone ESM bytes, with linker/dynamic imports denied. Node's
   VM API is not a security isolation boundary. A trusted module can still misuse
   ambient process capabilities, retain an already delivered secret, perform
   untracked I/O, block the event loop, or ignore cancellation. Promise deadlines
   cannot preempt a synchronous infinite loop. External process supervision/restart
   is required in those cases; hostile code must wait for the later isolated path.
2. G3 supports **unary operations with idempotency=none only**. Unsupported stream,
   provider-idempotency and IPC descriptors fail closed before evaluation. This is
   the minimal Echo substrate, not a claim of full ACAP transport conformance.
3. Quiesce uses immediate call cancellation (zero admission/drain grace); then waits
   up to `cleanupMs` for each disposer and cooperative outstanding work. Cleanup
   failure stays FAILED and reports `restartRequired`; `unsettledWork` is visible.
   Finite asynchronous tests prove broker/resource reclamation, not OS-side rollback.
4. The loader accepts a bounded, in-memory single-package inventory and standalone
   ESM entrypoint. It is not yet a production installer, archive extractor, dependency
   bundler, signing service, journal, SDK, service manager or offline distribution system.
5. The Host object is an **operator-only in-process API**. It is not an unauthenticated
   network endpoint and is never given to modules. `identity`/`context` are operator
   test/integration hooks; host exposure over a network would require real authentication.
6. Trust state requires one owner process and an operator-protected local directory.
   Concurrent-writer coordination, host-root compromise, backup rollback, hardware
   monotonic clocks and production root-key custody are not solved by this prototype.
   `initialize:true` is an explicit new-Cell provisioning action, not restart recovery.
   Restart with existing state; missing state with `initialize:false` fails closed.
7. Audit is a bounded local memory queue, not a durable external audit sink.
   `inspect` returns the latest 256 records plus total count; operator `drainAudit`
   exports/clears the queue. No arbitrary plugin log text/payload is admitted.
8. Instance/grant/effect/scope-tombstone limits are finite lifetime qualification
   budgets. Exhaustion refuses further work rather than growing indefinitely.
   Production retention, eviction and performance tuning remain later work.
9. Node requires `--experimental-vm-modules`, explicit in scripts and CI. This
   dependency on an experimental Node API is a recorded engineering risk.
10. Successful scheduled unattended-upgrade execution and GitHub required-check
    enforcement remain distinct from this runtime's tests. GitHub stays private;
    the approved manual process does not technically prevent write-access bypass.
