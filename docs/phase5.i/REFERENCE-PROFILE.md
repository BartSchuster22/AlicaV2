# Phase5.I reference profile

This is a bounded, native, nonlaunching reference instance and operator-owned qualification profile, not a production service or general-purpose runtime. Supported host: Ubuntu 24.04 x86_64 with Linux namespaces, chroot, setpriv and the exact Node/Python inputs in toolchain-runtime-identities.json. DEV was qualified; DSH2 was inspected only and is NOT an installed or qualified reference host. Phase5.3 remains deferred.

Setup downloads and package preparation are a separate privileged/operator phase. Runtime uses a dedicated unprivileged account, clean environment, empty network namespace (loopback only), private mount/PID/IPC/UTS namespaces, cleared capabilities and no-new-privs. The final composition mounts immutable payload read-only/nosuid/nodev, separately exposes a real /dev/null (major 1/minor 3), and permits writes only to reference tmp/state/evidence. Namespace PID1 owns all descendants; namespace exit ends reference-owned processes only. No public port or host administration socket is mounted. OS procfs is confined to the new PID namespace. Initial staged runners used their documented predecessor enclosures; the stricter final enclosure is a composition prerequisite correction, not a claim that all earlier runners had identical mount flags.

The artifact is a composition of isolated supported component contexts, not an invented universal registry/daemon or universal principal. Catalog snapshots are selected explicitly. Source integrity, namespace admission, runtime grants, backend credentials and application authorization remain separate. Exact snapshot and descriptor inventory: CAPABILITY-SNAPSHOT-INVENTORY.json and capability-snapshots/.

H and K have separately pinned source, environments and homes. H: c04e9a1d0dfa4abbefe4b256428e645abaacfe88; K: 536802c00e4f93061fc46b134dc029ff695f364f. H metadata comes from operator CLI profile list/show, not ACAP agent/session discovery. Its real accepted execute-only adapter is registered without an inference runner; execution authority is absent. The approved prerequisite boundary is native metadata PLUS separately evidenced unchanged adapter registration/denial/disposal/reconstruction. There is no ACAP discovery invention.

D uses the real Decision service, real Jev provider and installed SDK consumer with an explicitly injected OFFLINE_PROVIDER transport. The remote/provider response is MOCK, not inference. M uses actual MemoryV4 through its accepted native Python bridge and private SQLite state. G uses actual Doghouse; inputs are synthetic signals from authorized service-source plugins. K uses actual pinned Hermes Kanban and accepted real credential-provider mode on a namespace-only loopback listener. A fresh temporary backend credential is generated at qualification time, never copied from production and never published.

Mutable state owners: P2 record service owns its reference store; MemoryV4 owns its SQLite store and idempotency ledger; Doghouse owns incident data; Hermes Kanban owns its private database. Adapters do not invent replacement state authority. Profile and fixture configuration is operator-owned. Runtime instance IDs, source sequence/cursors and timestamps are not global identities or reproduction equality criteria.
