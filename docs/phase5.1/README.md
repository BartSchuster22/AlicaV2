## Architecture and admitted surface

`services/memoryv4/app/domain.py` owns governed operations, authority checks and semantic audit outcomes. `ports.py` is the explicit Store boundary; `storage.py` is the SQLite implementation. HTTP `main.py` only adapts transport/auth/error/ETag concerns to that domain. `candidates.py` and the private bounded `bridge.py` adapt the same domain to the frozen public SDK provider in `provider.mjs`. No second memory database, custom ACAP binding or Kernel/Foundation API was added. The default physical service store is SQLite; the ACAP provider requires explicit absolute Python/store paths from trusted operator composition.

Candidates v2 is a breaking, separately identified contract. Only v2 is admitted/implemented by this candidate. v1 proposal, parent review and blocked tests remain historical evidence, not an alias. Genuine parent review is `catalog/proposals/memory-candidates-v2/parent.review.json`; its application is `review-receipt.json`. Local experimental admission and real snapshot are under `catalog/releases/phase51-memory-v2/`. M7 is `evidence/admitted-m7.json`; preimplementation fixture snapshots remain explicitly synthetic.

`requestKey` is mandatory create payload data, not authority. Host idempotency is `none`. Each attempt passes current Host/domain checks; the shared transactional ledger binds operation, trusted actor, key, canonical request and original result. Same-domain restart/replay retains original IDs and results for at least 24 hours (currently no automatic expiry). Never discard this authoritative ledger as rebuildable. Explicit retry after ambiguous completion uses the SAME requestKey; no automatic retry. The private prefix separates accidental wire-key collisions, not principals. Authority comes only from the operator resolver keyed by genuine Host caller principal/instance/scope; request fields cannot grant scope, actor or permissions. See the reviewed v2 SEMANTICS and CHANGE documents for exact limits and migration.
