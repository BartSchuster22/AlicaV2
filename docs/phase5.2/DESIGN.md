# D5–D8 design candidate — NOT FROZEN / independent review required

This is a reviewable contract, not implemented behavior. D0–D4 precede it. No runtime refactor is authorized until genuine independent design review, PROPOSED disposition, and D8 validations are recorded. The proposer cannot write the review decision.

## D5 canonical assurance model and historical claim

Explicit choice: historical SEMANTIC MAPPING plus canonical exchange. NOT historical Doghouse JSON/Markdown/directory-format compatibility. No production incident files are imported and no claim of lossless old arbitrary diagnostics, counter reconstruction or original-format migration. Historical synthetic classifications preserve their label, historical rule ID/version and provenance as HISTORICAL_ONLY, never reassessed as the new rule. Old service_id maps to historical target, created_at to historical timestamp, incident_key to evidence correlation reference, reason/diagnostics only to sanitized evidence; absent occurrences cannot be invented. Old report-only/restart/kill flags are historical evidence, never authority. Exact prior semantics are in D2 ADR.

Authoritative portable state: Observation, Incident, Acknowledgement, rule-specific Resolution, bounded EvidenceReference, and minimal continuation data. Capability model is a selected public projection; canonical exchange is richer; store layout is private. Stable observation/incident IDs do not encode filesystem paths or target credentials.

Observation fields: id (opaque canonical ID, SHA256 of canonical producer-principal/scope/target/sourceObservationId tuple), sourceObservationId (stable source observation ID), producer (broker principal+instance provenance), observer (local assurance adapter identity at receipt), target, scope, occurredAtMs (source time), receivedAtMs (local clock), observedAtMs (source measurement time), eventId/sourceScope/scopeGeneration/sequence/timeMs envelope provenance, signal FAIL or RECOVER, ruleId/version, bounded evidence reference. Local authorization is checked before a record becomes evidence. Producer authenticity does not authenticate arbitrary claimed targets: local registration must match producer principal, current instance/generation, broker scope and target exactly. No caller-supplied observer or producer identity.

Incident fields: opaque id; type availability; target/scope; classification unavailable; firstObservedAtMs/lastObservedAtMs; status OPEN/ACKNOWLEDGED/RESOLVED; occurrenceCount; ordered occurrence observation IDs; ruleId/version; evidence references; acknowledgement history; resolution history; correlation key; window anchors; last distinct observation; bounded dedupe identities; recovery state. Canonical types must reject unknown fields and privileged material, not ignore it.

DERIVED: query indexes, self-health calculations, compatible-rule lookup. EPHEMERAL/nonportable: local identity/target registrations, ACAP grants, credentials, current observer identity, subscription handles, queues, paths, store handles, metric counters. EVIDENCE: original producer/observer/target/scope labels and rule provenance, not transferable authority. Imported acknowledgement actor is historical, not a principal mapping.

## D6 deterministic lifecycle, temporal and continuity contract

One rule: availability-v1 version1.0.0. One distinct authorized FAIL opens an incident; each further distinct in-order FAIL for same scope/target/rule increments occurrenceCount exactly once, whether OPEN or ACKNOWLEDGED. ACKNOWLEDGED retains incident identity and still needs observed recovery. One subsequent authorized RECOVER with same target/scope/rule and strictly newer event time resolves; unrelated or stale recovery cannot resolve. Silence, observer failure, queue loss or store failure NEVER implies recovery. A later FAIL after RESOLVED creates a NEW incident, not reopening/mutating history. Correlation key is exact scope+target+ruleId+version, never cross-scope; no time-based auto-resolution. A 24h active correlation window is a capacity/continuity bound, not an expiry-based resolution: after it, reject further ingestion with FAILED_PRECONDITION pending separately governed archival handling, rather than splitting an OPEN incident silently.

Acknowledgement IN: first successful acknowledgement records local mapped actor, receipt time and stable request ID; allowed OPEN->ACKNOWLEDGED, no repeated transition for exact retry. Distinct later acknowledgement returns existing acknowledged state without overwriting first actor; RESOLVED acknowledgement fails FAILED_PRECONDITION. Annotations DEFERRED. Manual resolution DEFERRED. No descriptor/schema/manual mutation backdoor; manual-resolution authorization tests are NOT_APPLICABLE because operation is absent, plus unknown-operation rejection test.

Time uses safe integer UTC milliseconds. Maximum source future skew5s and maximum age5min at initial ingestion. observedAtMs <= occurredAtMs <= receivedAtMs+5s; observedAtMs may not be older than5min either. Last distinct event ordering is strictly by occurredAtMs; equal or older distinct timestamps are rejected, not silently treated as recovery. Exact duplicate check occurs after current authorization but BEFORE freshness checks, so old redelivery returns duplicate without changing assessment. Same observation ID with different canonical signal content is CONFLICT. Broker event IDs are evidence; source stable observation ID plus producer principal+scope+target is durable dedupe identity across broker restart/redelivery. Current local instance may differ after import only via explicit current operator registration, not imported instance authority.

Bounds:16 registered targets,64 total incidents,256 retained observations/dedupe identities total,32 occurrences/incident,16 acknowledgements total, evidence one allowlisted code plus SHA256 reference per observation (no free text, URL, logs or credential-bearing arbitrary payload);64-byte identifiers (principal/instance/scope up to128 where Host permits), query page1–16. Reject excess atomically RESOURCE_EXHAUSTED; NEVER evict live dedupe or truncate authoritative history to appear successful. Total exchange <=1MiB; single signal <=4KiB; one serialized store writer, pending ingestion queue8; refuse overload, record self-health degradation. Underlying broker's bounded best-effort queue is separate and may terminate a subscription; no end-to-end exactly-once delivery guarantee. Target freshness5min, unknown coverage at startup until observed, stale/failed observer never fleet recovery.

### F1 amendment — measurable cooperative deadlines and shutdown

Fixed qualification defaults (not new configuration or Foundation contracts): each get/list/acknowledge operation has a 1000ms total budget from adapter admission, including any store wait; each signal has a 1000ms ingestion budget from adapter receipt, including at most 250ms pending-queue wait. Use the earlier of these local deadlines and any applicable Host/caller deadline; never extend a caller deadline. Measure local elapsed budgets with a monotonic clock, converting an absolute caller deadline to remaining duration once at admission. Broker delivery time before adapter receipt is outside the ingestion budget and remains subject to the existing freshness checks. A full pending queue is refused immediately with RESOURCE_EXHAUSTED; an expired queue entry is removed without domain mutation, records a dropped/expired signal and degrades self-health. At dequeue, recheck both the 250ms wait limit and total budget before starting work; no late entry may start simply because its timer callback was delayed.

At admission, before store work, before entering the atomic commit sequence, and before returning a result, check deadline/cancellation: expiration is DEADLINE_EXCEEDED and explicit cancellation is CANCELLED (already-expired deadline takes precedence when both are observed). Work not yet committing is refused without mutation. Signal failure is recorded locally as rejection/drop/self-health evidence, NOT an assurance incident and NOT a synchronous producer failure response: public event emit admission does not acknowledge domain persistence. Once the store commit sequence has begun, finish or fail that consistency sequence without attempting cancellation-driven rollback. Cancellation/timeout observed afterwards suppresses success delivery but does not undo a committed generation; acknowledge retries use the same requestId and signal redelivery uses its stable observation identity to resolve an uncertain result. Never claim a timeout proves that no write occurred.

Shutdown enters STOPPING immediately when invoked on the event loop, refuses new calls/signals with UNAVAILABLE (signals recorded locally), and allows previously admitted work to drain under its original deadlines for at most 2000ms from stop initiation. At the earlier operation deadline or shutdown drain expiry, cancel pending/noncommitting work; do not begin another commit. Dispose listener/provision/effects and close store ownership only after in-flight commit work has quiesced. Repeated stop requests share the same stop outcome and do not reset budgets. If drain/cleanup is incomplete at the 2000ms deadline, report DEADLINE_EXCEEDED with cleanup incomplete at the next schedulable checkpoint, remain STOPPING/UNAVAILABLE and retain ownership needed by unfinished I/O; never report clean shutdown or release writer ownership while a commit may still run. No process kill, restart, supervisor or new control authority is introduced.

These are cooperative admission/wait/drain budgets and observable timeout rules, NOT hard wall-clock preemption guarantees. Native synchronous filesystem calls, especially fsync, cannot be interrupted by these checks and can block the event loop past any deadline; refusal, timeout reporting and cleanup then occur only after control returns. No finite upper bound on blocked-kernel I/O or total process termination is claimed. Qualification must separately measure responsive-I/O operation/wait/drain behavior and test delayed-I/O/commit-boundary timeout outcomes without asserting hard preemption. Before implementation/freeze closure this is a design commitment only, not executed deadline or shutdown conformance.

Minimal continuation: exact rule ID/version, correlation key, incident identity/status, ordered retained occurrences and count, last distinct observation including time/content hash, all retained dedupe keys/content hashes, first/window anchor, recovery observation and acknowledgement. Atomic commit groups incident/observation/dedupe/ack changes. Normal restart restores all; failed commit exposes no partial domain mutation. Crash fixture interrupts before/after replace, verifies either old or new consistent generation. Proposed native store: one validated bounded JSON generation in operator-owned directory, exclusive single-writer ownership, temp-file+fsync+atomic replace+directory fsync; private store metadata not canonical authority. No filesystem sandbox/power-loss certification. Corrupt or foreign store fails closed; not replaced with empty state.

Canonical export: deterministic sorted JSON; explicit assurance.exchange/v1 header and rules; no timestamp regeneration; validate all relationships and caps; exclude local authority and arbitrary caches. Import only into verified EMPTY fresh isolated target, complete validate before atomic commit; repeated/nonempty import fails. COMPATIBLE: exact understood rule semantics plus all continuation invariants, permits future continuation ONLY after independently supplied local matching authorization. HISTORICAL_ONLY: syntactically valid records with unavailable historical rule semantics are preserved/queryable and cannot auto-continue, acknowledge or resolve; matching new observations cannot attach to them. REJECTED: malformed/unsafe/unknown privileged fields, inconsistent counts, collisions, broken references, illegal transitions, incompatible declared schema, invalid timestamps or oversized state. Unknown rule semantics never silently inherit newer meaning. Export/import/re-export canonical semantics must match. Test pre-export processed event redelivered post-import (same stable observation key and content, possibly new broker event ID) under current authorization: no new occurrence. Without current authorization: denied, even for duplicate.

## D7 capability proposal and public bindings

Exactly acap://alica.io/assurance/incidents@1, io.alica.assurance.incidents v1.0.0: get(scope,id), list(scope,offset,limit), acknowledge(scope,id,requestId). No submit/export/import/admin/control operation. Signal arrives via reviewed io.alica.assurance.signal typed event (source observation ID, target, source times, FAIL/RECOVER, evidence code/hash); scope and producer come from trusted broker, not payload. A single generic signal event accompanies the minimum capability, not a new Foundation interface. Permissions assurance.read and assurance.acknowledge are labels, not grants. Host operation grants and separately resolved current local actor/data-scope map are both required. Requested scope must match mapped data scope exactly; no prefix/ancestor inference. All handler calls enter the same domain API; never manipulate store directly. Errors preserve denied/not-found/unavailable/invalid/conflict distinctions without leaking cross-scope existence. get/list expose only same-scope records. Query projection includes status, classification, target, occurrences, times, rule/version, historical/compatible disposition and first acknowledgement; public consumers never import Doghouse internals.

Acknowledgement request ID is durable idempotency content, bound to mapped actor+scope, collision on different incident is CONFLICT. No need to promise ACAP generic idempotency option: operation is idempotency:none at transport, explicit domain requestId semantics in contract. Mutation linearization at atomic commit; caller timeout after commit does not roll back. Check cancellation/deadline before commit; exact requestId retry resolves uncertain result. Development proposal/definition uses proposed metadata but this is NOT governance PROPOSED until distinct reviewProposal succeeds. No fabricated review or admission.

## D8 ServiceManifest and native topology

Public-host-inproc-v1; stateful assurance ownership, no MemoryV4 dependencies, no required container/systemd/LLM. Read-only public SDK adapter registers capability/event listener under operator-created Host identity. Operator injects narrowly scoped native store and local identity registrations; native resource is not available by private Kernel import or plugin filesystem import. Exact resource bridge topology must follow accepted Foundation inproc approach and be covered in D12/D13; no hostile-code confinement claim. Data authoritative assurance.records; derived query indexes rebuilt at startup; configuration restart-only; secrets empty; self-owned READY/DEGRADED/UNAVAILABLE health.

Self-health reports store availability, event-consumption/subscription state, last receipt, per-registered-target freshness/coverage, drops/rejections; does not replace producer health. Startup validate config/store then subscribe/provide; stop refuses new work, drains bounded admitted operations, disposes listeners/provision/effects; no background timers required. Backup declaration required/stopped, migration same-schema-only; execution NOT_TESTED unless actually separately exercised, never inferred from exchange. Canonical exchange != backup.

D8 design validation uses DEV-ONLY fixture snapshot because frozen consumeSnapshot rejects proposed definitions. Experimental metadata within that fixture is ONLY a validator input, NOT admission/evidence/release. No alteration to frozen Catalog/Foundation. Repeat against actual EXPERIMENTAL admission snapshot after implemented D13 conformance and D13b real maintainer transition. trustVerified=false throughout.
