## Useful executable slice

- `tools/g7-supervisor.py` is a Linux host custodian. It opens the existing private Cell root component-by-component with no-follow directory descriptors, checks owner/mode, and holds its lifetime exclusive nonblocking flock. This slice requires a successfully initialized but never-installed Cell, an absolute trusted Node executable, and a private input file containing exactly archive/trust/authorization. It does not initialize or restart an existing runtime.
- Before spawning an owner, it exclusively creates and fsyncs `supervision/`. Residue is a durable no-takeover fence, NOT proof of a live process, readiness, or death. Direct Cell construction refuses residue even after both processes have exited. No stale socket/marker deletion or automatic reconciliation is implemented.
- Native `adoptRoot` validates an inherited descriptor against an independently no-follow-opened root inode, UID, directory type and mode. A separately opened flock probe must conflict; locking the inherited description must succeed. A CLOEXEC duplicate retains the SAME open-file-description lock. Closing a duplicate does not unlock the custodian's description; there is no LOCK_UN handoff window. The owner closes the original inherited descriptor before provider creation.
- The real Cell continues to use `/proc/<live owner PID>/fd/<held FD>/kernel.json`. Its public Kernel bootstrap/discovery/startProfile/require/synthetic echo/unchanged consumer/shutdown remain authoritative. No marker or child PID is used as readiness. No new provider callbacks, supplied clock, Kernel report substitution or production test option was introduced.
- A separate socketpair carries fixed host phase messages/acknowledgments. Activation cannot begin until the custodian acknowledges the phase. Real monotonic external verification/activation/cleanup budgets use the unchanged 300000/30000/30000 ms limits. Nested cleanup does not reset the enclosing verification/activation deadline. An admin stop starts its external cleanup budget BEFORE sending to a potentially blocked owner, and keeps it through final status and exact-child reap. A phase message observed after expiry cannot reset the deadline.
- Timeout/error latches uncertainty, signals the owner using Linux pidfd, and keeps the flock and durable fence. Exact owner exit is observed via pidfd and `Popen.poll()`/waitpid on that child, not PID-existence polling. Owner death alone NEVER establishes descendant reap; forced kill is never relabeled STOPPED. No restart occurs. A clean STOPPED response requires the existing Cell's actual clean public Kernel shutdown report followed by a normal exit/reap of the exact owner child.
- `--launch` starts the custodian in a new session with closed client stdio and exits. Its output is only a spawn receipt (`runtime: NOT_OBSERVED`), never installation success. Real authenticated status after installation is the runtime observation. Foreground mode retains stderr for diagnosis; detached launch currently discards stderr and has no durable diagnostic log.

## Local endpoint and supported surface

The socket is `<Cell>/supervision/admin.sock`, mode 0600 under a freshly created 0700 directory, within the verified 0700 Cell. The supervisor uses actual Linux SO_PEERCRED and checks UID; no caller PID/UID fields are accepted. The private incarnation record contains a random UUID, supervisor PID and monotonic start identity. The PID is informational, not death authority. Same-UID compromise remains explicitly outside the confinement guarantee; an authorized same-UID administrator can modify files/code and is not defended against by checksums or this protocol.

Only exact-schema `status` and `stop` work. Status asks the live owner for a new public Kernel observation, rather than presenting a cached RUNNING observation as fresh. `start` and `verify` are valid frozen operations but return DENIED. Upgrade/install/backup/restore/recover are not admin operations and fail closed. Errors with an available snapshot use only frozen response fields/enumerated codes; invalid framing/schema and unknown selection close without an invented response. Conflict/denial responses do not certify cached runtime liveness. Expected sequence and incarnation are checked; an active request conflicts immediately. Disconnect is not cancellation. No queued mutation replay.

Frames use a four-byte big-endian byte length, strict UTF-8/JSON, duplicate-key rejection, safe integers, depth <=32 and body <=65536 bytes. There are at most eight admitted connections, each with a 30-second connection budget; buffers are bounded. Requests with unknown fields/operations, invalid Unicode, empty/oversized frames, multiple or trailing frames fail closed.

## Exact unresolved contract / compatibility gaps

1. Frozen `adminResponse` REQUIRES a nonnegative integer `sequence` and `acceptedDigest` (digest or null), but has no unknown-selection representation. If first activation dies/blocks during publication, the responsive custodian cannot know whether accepted replacement/fsync completed without potentially blocking itself on filesystem IO. It therefore has no truthful complete error envelope at that instant. This candidate closes the connection and retains custody instead of asserting sequence=0/null or stale selection. A structured NEEDS_OPERATOR response during this unknown-selection window remains unavailable. This is not permission to weaken the schema or claim durable reconciliation.
2. To reject delayed trailing bytes BEFORE executing stop, this candidate waits for request write-EOF (client `shutdown(SHUT_WR)` / Node `socket.end(frame)`). The frozen review specifies length framing and one request/response but does not explicitly require write-half-close. A client that sends only the full length-framed request and then waits without half-closing receives no response before the unchanged connection ceiling. This additional sealing requirement is an unresolved interoperability restriction, NOT approved revised framing or full R1 admin qualification. Parent must resolve it explicitly before treating this as the general frozen admin transport.
3. External supervision remains ordinary Linux scheduling, not a hard-real-time guarantee. A blocked/uninterruptible filesystem syscall may complete after SIGKILL is requested; a pending rename/fsync cannot be undone. The supervisor can stop admission, revoke the owner's execution via pidfd signal, retain custody and report/retain uncertainty. It cannot certify that every syscall finishes within the numeric ceiling. No new owner may enter while disposition is uncertain. Verification budget starts during child setup; initial custodian filesystem setup itself is not made nonblocking. The prior in-process hard-deadline limitation is not erased.

## Running the component (development only)

From the development checkout with pinned Node on PATH and native/public packages already built:

    python3 tools/g7-supervisor.py --launch "$PWD/.tools/node/bin/node" /absolute/initialized-cell /absolute/private-inputs.json

Input directory must be 0700, input regular file 0600 and owner-owned. The input object has exactly archive, trust, authorization. Root must already have been initialized by the existing Cell CLI and have no transactions requiring recovery. Read the private incarnation, then send a frozen status/stop frame with expectedSequence=1 after successful first install; this candidate requires write-half-close. No production signing or owner acceptance is authorized by this command.

All source is left uncommitted for parent review/testing/hash binding. No commit/push, agent workers, scheduled jobs, other-profile edits, service migration or production/custody signing.
