## Implemented missing successful case

The continuously owned maintenance wrapper used to abandon its coordinator on every target activation error, even when the real public Kernel had completed clean shutdown, the failed transaction was durably ABORTED, and the prior accepted selection had never moved. That unnecessarily discarded genuine cleanup authority.

`CellPreparation.ownedMaintain()` now retains that authority only for a private, lexically minted error identity from `#activate`, after its existing actual cleanup and durable ABORTED path. Public `runtime: STOPPED`, journal bytes, socket state, pidfd death and serialized receipts cannot enter the exception. The wrapper rechecks the watchdog, clean stopped state, absence of a live host, unchanged prior selection and terminal journal history. Other failures still abandon/fence.

The original maintenance process remains the custodian of its own actual target Kernel cleanup and continuously held root lock; its exact spawned coordinator remains the independent watchdog. No process is adopted from filesystem residue. No descriptor, boolean or public recovery certificate is accepted as authority.

A distinct explicit `ownedRecoverPrior(currentInputs)` revalidates the selected prior through the existing exact-reinstall path: independently supplied current trust and authorization, retained release bytes AND requested archive bytes, original Cell identity/history/floors, and public Kernel bootstrap against a private verbatim copy of the opaque original Kernel state. It never decodes/rewrites that original state to manufacture continuity. The pending recovery state blocks serving; the existing serving-phase precondition also refuses another maintenance/upgrade attempt after the abort. Success clears only the private pending choice; it does not change selection, revise ABORTED history, restart the failed target, or replay mutations.

Serving remains a separate `ownedServe()` operation. It repeats current authority validation and launches a fresh actual owner under the original coordinator, using original Cell Kernel state, fresh grants/readiness and real synthetic calls. The last-known-good release is not automatically served. Final ordinary closure still normally reaps the coordinator and leaves the original supervision fence; a later detached invocation cannot reconstruct custody.

No new live admin operation is introduced. A1+B1 EOF/framing/version rules, stop/start semantics, shared aggregate eight connections, 30 s admin/activation/cleanup budgets and 300 s verification budget are unchanged. The watchdog does not reset its maintenance deadline for the explicit recovery call.

## Narrow limitation, not a universal recovery exception

These changes close the concrete clean failed-target/prior-selection continuation gap. They do NOT implement successful detached post-crash reconciliation of an activated Cell. Existing abrupt-loss tests require denial because there is no surviving independent process with authority to certify all affected cleanup and publication durability. R1's invalid-trust/uncertain-reap row applies; the matching-pointer row cannot waive it.

The current architecture intentionally makes the coordinator contain the foreground maintenance process on authority loss, not replace it or adopt unknown processes. General post-crash successful reconciliation would need a separately designed surviving cleanup owner/reconciler with genuine continuously retained authority, complete lifecycle histories, independent current trust, and new real-process qualification. Merely accepting a stored CLEAN, pidfd death, socket absence or changing a fence flag is not that design. No owner exception to these rules is presumed. If a Cell's authority is irretrievably lost, only an independently owner-authorized recovery procedure (including current trust/source-stopped proof where applicable) may proceed; this worker does not invent one.

The R1 model's successful target-crash condition remains a conditional requirement; it is not newly certified by passing denial tests. G7-10's complete durability/host qualification is still open. This is an explicit boundary rather than a claim that all G7 recovery work is complete. Other authorized engineering need not wait: the runtime dependency subassembly is implemented and exercised in this same handoff.

## Assembly/SBOM prerequisite delivered

`tools/g7-runtime-dependencies.mjs` materializes the locked AJV production dependency closure under an exclusively created destination. It checks installed manifest identity/version and dependency edges against the lock, refuses unsupported dependency categories/nested resolution/symlinks/nonregular files, uses bundle-compatible unscoped paths, and copies actual license files. It emits `sbom/dependencies.json` with every actual staged file's byte length and raw SHA256, package dependency edges, source lock digest and upstream integrity/resolution metadata. Output is deterministic across two independently created destinations. No npm/pip/OS installation, hook, download, signing or candidate execution occurs during assembly.

Tests execute actual staged AJV in an isolated working directory, with no inherited NODE_PATH/NODE_OPTIONS, and assert every loaded dependency comes from the staged tree. They verify complete file coverage, license coverage, byte/hash equality and exclusive no-overwrite behavior. Negative tests remove a required lock node, change a version/license, add a symlink or unsupported optional dependency; all fail before output creation.

The old `/home/herman/g7-bundle-inventory-preparation` was read and reused as preparation only. Its old source/native observations are NOT promoted to current provenance. The new materialized files and execution are actual development evidence.

This is a dependency SUBASSEMBLY, not the frozen complete `sbom/sbom.json` delivery or a signed bundle. The inventory explicitly lists omissions: application AST import transformation, Node embedded components, Python/stdlib/OS ABI, native output dependency closure, age/bootstrap, complete licensing/provenance and two-host qualification. Upstream tarball integrity strings are lock provenance, not a claim that installed files were reverified against downloaded tarballs. The tool is trusted single-writer build-time materialization, not an untrusted archive extractor or race-resistant Cell mutation API.
