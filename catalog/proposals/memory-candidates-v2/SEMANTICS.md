# Candidates v2 — proposed domain request replay

UNREVIEWED additive draft. Not admitted, experimental, published or owner accepted. Original v1 packet and genuine review remain immutable evidence; no review carries over.

## Capability and authority

One capability `acap://alica.io/memory/candidates@2`, descriptor `io.alica.memory.candidates` version2.0.0, create/get/search. Candidate projection, working-only role/lifecycle, bounds, scope hierarchy, errors, lexical pagination and provenance restrictions are unchanged from ../memory-candidates/SEMANTICS.md, EXCEPT the original create transport-idempotency section is replaced completely by the rules below. That original document is evidence, not authority to use v1 transport idempotency in v2.

Create only active/working, author_only candidates. Actor, root and permissions come from trusted Host execution context mapped by the operator on every attempt. Scope in the payload is a requested target, never a grant. No caller actor/identity/grants/promotion/import fields. A consumer request key is not a credential, grant, identity, or source-authentication proof. Explicit memory.create-working/read/search grants remain narrowed to configured actor/root; no memory.admin/delegation. Get/search only expose currently visible active/working records without silent truncation, fetching artifact bytes, or implicit public visibility. Search remains bounded lexical retrieval, not advanced retrieval. Missing and outage remain distinct.

## Host guarantee versus domain guarantee

All operations declare Host `idempotency: none`; `idempotencyPolicy` is absent. `CallOptions.idempotencyKey` MUST NOT be supplied and is rejected by unchanged public ContractSession. No Host instance or durable cache is claimed. Host still enforces schemas, package-bound descriptor digest, operation grants, current scope/lifecycle, deadlines, cancellation and ownership/disposal. SDK delegates to those public interfaces; it does not manufacture authority.

Create additionally REQUIRES payload `requestKey`, 8–128 ASCII characters, first alphanumeric, remainder alphanumeric/dot/underscore/hyphen. The descriptor enforces string/length; adapter enforces alphabet. Unknown fields fail validation. Key identifies one logical creation request within a stable trusted domain actor and authoritative target domain. It is persisted by the consumer for explicit retries, independent of transient Host requestId, principal/instance/scope-generation identifiers. Consumer must never use a new key merely because response delivery was uncertain.

Provider MUST durably and atomically persist mutation, success audit and request/result binding before reporting success. For at least86400000ms after commit, across normal child/provider/complete Host restart against the same authoritative domain, same trusted actor + operation namespace + requestKey + same normalized complete mutation payload MUST return the original successful projected result (including stable ID and original version). Same actor/key but changed content, provenance, requested scope or other mutation field MUST return CONFLICT, not another create. Normalization is existing RecordCreate domain validation/defaults, not raw JSON whitespace/key ordering. Different actors have independent key namespaces and cannot use a key to retrieve another actor's result. Existing state paths, grants or configuration cannot be selected by payload.

EVERY replay attempt MUST first pass current Host authorization, trusted operator mapping and domain scope/create permission checks. Removed mappings, narrowed root or revoked create permission deny even a previously successful key; reauthorization can allow subsequent same-key replay. Host error/success caching must not bypass these checks. Authorization is checked at admission/domain invocation; no new promise of cross-process atomic policy revocation during an already-admitted SQLite transaction. Host continues its own pre/post-completion authorization/cancellation checks.

The successful replay is the original creation receipt, not a read of mutable current state. It does not restore/re-promote/unarchive a subsequently changed record. Use get/search for current state, which remain working-only. Domain-denied attempts can produce existing denial audit; replay never duplicates the successful creation/audit. Reads/search are not mutated into replayable operations.

## Failure and retention

Cancellation/deadline/child crash/response loss do NOT promise rollback. A write may be committed before response delivery fails. No automatic retry. Consumer explicitly retries same key and same payload after obtaining currently valid authority. An uncommitted transaction leaves no successful mutation/binding; a committed transaction leaves both. Provider must not evict the binding within24h; if capacity cannot safely retain a new binding, fail before committing that new mutation rather than silently dropping an existing guarantee.

Prototype reuses existing Store `BEGIN IMMEDIATE`, `_idempotency_replay`, `_insert_record`, `_save_idempotency` transaction without product/domain edits. Adapter maps key to `acap.candidates.v2:` + requestKey (within existing200-character bound); actor is a separate Store key column. Prefix avoids accidental cross-adapter collisions, not an authorization boundary against the same actor's separately authorized HTTP access. Ledger compares operation and normalized request hash; stores original response JSON. Current implementation has no expiry/eviction path and retains successful bindings indefinitely in that domain, stronger than minimum24h. Failed attempts are not memoized as successful domain requests. No lower durability guarantee is substituted.

Ledger is authoritative retained provider state, distinct from portable memory graph; normal restart must retain it. Deleting/resetting/replacing a domain or importing canonical graph into a different fresh domain is not normal restart and does not transfer old request guarantees. No live restoration/cutover is authorized here. Preserve the ledger in same-domain recovery; portability/adoption rules remain separately gated. Keys must not be recycled while retained: later reuse may still conflict after24h.

## Evidence boundaries

`phase51/redesign/test.mjs` invokes real frozen Host/SDK and actual Python shared domain against disposable SQLite fixtures in an isolated network namespace. It exercises original stable result across complete Host restart with changed consumer identity; domain/Host reauthorization; actor isolation; changed-request conflict; forged fields/old wire rejection; committed response loss then same-Host retry; and25h-aged ledger metadata followed by restart/replay. Age manipulation is confined to a named fixture database: this is an accelerated retention-boundary test plus no-eviction source inspection, NOT a24h elapsed soak. External artifact bytes, production, canonical import/export, container qualification and complete Foundation/native M11/M12 are not tested by this diagnostic.
